# 整理券システム固有の緊急時シナリオ

## 使い方

異常が発生したら、該当するシナリオ番号を確認し、次の順で対応します。

1. 操作を止め、同じボタンを連打しない。
2. 対象日、整理券コード、ゲーム、枠時刻、席番号、発生時刻を記録する。
3. 「直ちに行うこと」を実施する。
4. 復旧条件を満たすまで、推測で処理を続けない。
5. 解決しない場合は責任者または管理者へ引き継ぐ。

## S01 発券したのに完了画面や整理券コードが表示されない

**発生例**：発券ボタンを押した後に画面が止まる、通信エラーが表示される、コードが不明。

**直ちに行うこと**

1. 発券ボタンを再度押さない。
2. 発生時刻、選択したゲーム、画面表示を記録する。
3. 管理者に、発券が成功しているかデータ確認を依頼する。
4. 成功・失敗が確認できるまで、同じ来場者へ再発券しない。

**復旧条件**：発券済みコードが1件だけ確認できた、または発券失敗が確認できた。

**禁止事項**：画面が見えないことだけを理由に再発券する。

## S02 同じ来場者に二重発券された疑いがある

**直ちに行うこと**

1. 2枚のコード、発券時刻、ゲームを記録する。
2. どちらもチェックインせず、責任者へ保留として報告する。
3. 採用するコードを責任者が決定する。
4. 不採用コードは、勝手に削除せず取消または保留として記録する。

**復旧条件**：採用コードが1つに決まり、もう一方の扱いが記録された。

## S03 整理券コードが検索で見つからない

**直ちに行うこと**

1. 対象日を確認する。
2. 通常 `No. 001`、優先 `P001`、即時 `I001` の形式を確認する。
3. ゼロ埋め、英字、全角・半角、入力の前後の空白を確認する。
4. 紙の整理券のゲーム名と発券時刻を照合する。
5. 見つかるまでチェックインや再発券を行わない。

**復旧条件**：画面上の1件と紙の整理券が一致した。

## S04 別の来場者の整理券をチェックインしそうになった

**直ちに行うこと**

1. チェックインを中止する。
2. No.、ゲーム、枠時刻を来場者と読み合わせる。
3. 誤って処理した場合は、追加操作をせず管理者へ報告する。

**禁止事項**：氏名や自己申告だけでコードの不一致を上書きする。

**復旧条件**：画面のコード、紙のコード、来場者、ゲームが一致した。

## S05 チェックイン済みなのに一覧や割当候補に出ない

**直ちに行うこと**

1. ページ更新は1回だけ行う。
2. status、チェックイン時刻、assigned slot、assigned seat を確認する。
3. 取消済み、割当済み、別日、別ゲームでないか確認する。
4. 状態が一致しない場合は、再チェックインや再発券をせず管理者へ報告する。

**復旧条件**：チェックイン状態と割当候補の表示が一致した。

## S06 遅刻者が通常枠・調整枠のどちらにも表示されない

**直ちに行うこと**

1. 到着済みであることを確認する。
2. `is_late`、本来の定刻、最新の定刻、割当済み状態を確認する。
3. 調整枠の空席と通常枠の空席を確認する。
4. 管理者の判断なしに遅刻フラグや定刻を手動変更しない。
5. 空席へ入れる場合は、割当先と案内時刻を責任者が決定する。

**復旧条件**：割当先が画面と現場の両方で確認できた。

## S07 割当順位が「定刻 → 遅刻 → 前倒し」になっていない

**発生例**：前倒しが定刻者より先に割り当てられる、調整枠に定刻者が出る。

**直ちに行うこと**

1. 枠の割当を確定しない。
2. 対象枠が通常枠か調整枠かを確認する。
3. 定刻、遅刻、前倒しの各候補と表示順位を記録する。
4. 画面更新後も再現する場合は管理者へ報告する。

**期待する順序**

- 通常枠：定刻者 → 遅刻者 → 前倒し
- 調整枠：遅刻者 → 前倒し（定刻者は対象外）

**復旧条件**：プレビューと確定処理の候補順が一致した。

## S08 間違った席・枠・整理券を確定した

**直ちに行うこと**

1. 来場者を誤った席へ案内しない。
2. 対象枠、席、コード、確定時刻を記録する。
3. 同じ枠の追加割当を一時停止する。
4. 責任者が解除、振替、またはそのまま案内するか判断する。

**禁止事項**：状態を確認せず連続解除する、別の席へ上書きする。

**復旧条件**：画面上の割当と実際の席が一致した。

## S09 空席があるのに割当できない

**直ちに行うこと**

1. 席がメンテナンス中でないか確認する。
2. 枠が閉鎖済み、スキップ済み、または別の割当で埋まっていないか確認する。
3. 調整枠か通常枠かを確認する。
4. seat status、is_assigned、ticket status の不一致を記録する。
5. 画面上の空席だけを根拠に、手動で同じ席へ割り当てない。

**復旧条件**：空席の状態が画面・データ・現場で一致した。

## S10 席や枠をメンテナンス化した後に割当が崩れた

**直ちに行うこと**

1. 対象席または枠を新たに使用しない。
2. 予約済み・割当済みのチケットがないか確認する。
3. 影響する枠と整理券を記録する。
4. 最新の定刻が再計算された場合、本来の定刻との差分を確認する。
5. 振替や調整枠の使用は責任者が決定する。

**復旧条件**：メンテナンス対象を除いた空席、割当、最新の定刻が一致した。

## S11 遅延シフトや枠時刻を誤って変更した

**直ちに行うこと**

1. 追加の遅延シフトを実行しない。
2. 変更前後の時刻、対象枠、操作時刻を記録する。
3. 本来の定刻と最新の定刻を比較する。
4. 責任者が正しい開始時刻と影響範囲を決定する。
5. 来場者には確定した最新時刻だけを案内する。

**復旧条件**：タイムライン、チケットの最新定刻、現場案内が一致した。

## S12 調整枠を通常枠として扱ってしまった

**直ちに行うこと**

1. その枠の追加確定を止める。
2. 定刻者が調整枠に入っていないか確認する。
3. 遅刻者・前倒しの候補と、確定済みの席を記録する。
4. 責任者が解除・振替・継続利用を判断する。

**復旧条件**：調整枠から定刻者が除外され、遅刻者・前倒しの扱いが確定した。

## S13 即時チケット・優先チケットを誤発行した

**直ちに行うこと**

1. 発行コード、発行理由、ゲーム、発行時刻を記録する。
2. まだチェックインしていなければ、受付処理を保留する。
3. 責任者が有効・取消・通常扱いのいずれかを決定する。
4. 既に割当済みなら、現場へ案内せず責任者に引き継ぐ。

**禁止事項**：同じ異常に対して追加の即時チケットを発行する。

**復旧条件**：コードの有効性と割当順位が記録され、関係担当者へ共有された。

## S14 画面が更新されない・500エラー・通信エラー

**直ちに行うこと**

1. ボタンを連打せず、画面のエラー文を記録する。
2. 受付・発券・割当の操作を一時的に紙記録へ切り替える。
3. 管理者の指示でページ更新を1回だけ行う。
4. 復旧後、紙記録を1件ずつ照合してから入力する。

**禁止事項**：復旧確認前の再発券、同じ人の再チェックイン、独断のサーバー再起動。

**復旧条件**：管理者がデータ保存と画面表示の正常を確認した。

## S15 複数担当者が同じ枠を同時に操作している

**直ちに行うこと**

1. すべての担当者が操作を止める。
2. 枠ごとに操作担当者を1名に決める。
3. 直前の画面更新後に、確定済み席と空席を読み合わせる。
4. 途中状態の操作は、責任者の確認後に1回だけ再開する。

**復旧条件**：担当者、対象枠、次の操作が明確になった。

## S16 データベースの状態と画面・現場が一致しない

**発生例**：DB上は割当済みだが画面は空席、画面は確定だが現場は未案内。

**直ちに行うこと**

1. DBを直接変更しない。
2. 対象コード、枠、席、status、更新時刻を記録する。
3. 管理者がバックアップやログを確認する。
4. 現場の実態を優先して来場者を案内せず、責任者が復旧方針を決める。

**復旧条件**：バックエンド、画面、現場の3者で状態が一致した。

## 報告テンプレート

```text
シナリオ番号:
発生日時:
担当画面:
対象日:
整理券コード:
ゲーム:
枠時刻:
席・レーン:
画面表示:
実際の現場状態:
直前に行った操作:
来場者への案内:
現在の保留事項:
報告先・報告時刻:
```
